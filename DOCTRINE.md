# ARES Doctrine: The Constitutional Law of the System

ARES is not a "chatbot." It is a **High-Fidelity Interface for Intelligence**. 
It is a professional-grade orchestrator shell designed to bring cutting-edge AI research to the average person, polished as a mass-market software solution.

## I. The a-priori Model (The "First Law")
ARES is the **Orchestrator Shell**. It owns the User Relationship, the Identity, and the Memory.
- **Symmetry**: ARES does not compete with LLMs or frameworks (LangGraph, Paperclip, etc.). It **integrates** them via adapters.
- **Architecture**: `User UI` $\rightarrow$ `ARES Controller` $\rightarrow$ `Worker Adapter` $\rightarrow$ `Inference Engine`.
- **Identity**: ARES provides a stable identity and session store. Workers are replaceable engines.

## II. The "Glass Box" Principle (Transparency over Magic)
Magic is not the absence of understanding; magic is the elegance of the mechanism.
- **No Black Boxes**: Every consequential action must be inspectable.
- **The Completion Contract**: An action is not "Done" until it satisfies:
  1. **Outcome**: The task is completed correctly.
  2. **Model**: The mechanism (how it happened) is exposed.
  3. **Proof**: The user can verify the result via a real-world check.
  4. **Handoff**: The user understands the model enough to redo or adjust it.
- **Teaching as a Feature**: ARES optimizes for **User Competence**, not just task throughput.

## III. The Linguistic Standard (No Metaphor Creep)
Metaphors are for onboarding; nouns are for engineering.
- **Banned Metaphors**: No "Board," "Leo," "Hands," or "Control Plane" as structural architecture.
- **Canonical Nouns**: Use `User`, `Assistant`, `Worker`, `Adapter`, `Prompt`, `Weights`, `Injection`, `State`.
- **Intent over Text**: Bind user intent to actual file paths, API endpoints, or state changes—not to "personality" descriptions.

## IV. Success Metrics
ARES is successful when:
1. The user can la-priori predict how a change in the "Glass Box" (Tuning) will affect the "Surface" (Chat).
2. The system remains backend-agnostic (can switch from Hermes to Jaeger to a new Neural Net without losing identity).
3. The user feels more competent with their machine after using ARES, not more dependent.
