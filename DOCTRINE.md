# ARES doctrine

ARES is a transparent product interface for reasoning and action, not a second
agent runtime.

1. ARES owns the user experience and its own product metadata.
2. JaegerAI owns agent execution and authoritative runtime state.
3. Every durable datum and mutation has one declared owner.
4. Integrations use versioned, capability-negotiated contracts and fail closed.
5. Consequential actions are inspectable, approval-aware, and verifiable.
6. Product language uses concrete engineering nouns, not architecture metaphors.
7. A feature is complete only when its contract, route, UI, persistence,
   security checks, and end-to-end verification agree.
